# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An unofficial port of **LineageOS 24.0 (Android 17)** to the **Samsung Galaxy Tab S6 Lite (2020) LTE (`gta4xl`, SM-P615, Exynos 9611)**, packaged as a Podman build environment. LineageOS supports the device officially up to 23.2; the device trees (`android_device_samsung_gta4xl{,-common}`), the LineageOS kernel and TheMuppets' proprietary files have no `lineage-24.0` branch, while every `hardware/samsung*` dependency has one. `build.sh` syncs `lineage-24.0` with `ROOMSERVICE_BRANCHES=lineage-23.2` (roomservice falls back to 23.2 for the device repos), replaces the tablet's 4.14 kernel with a fork on Linux 4.19 (`6Xkljk8Vj7Tk1k4/android_kernel_samsung_gta4xl`, branch `gta4xl-4.19`), copies the proprietary files from `vendor_blobs/` (filled by `tools/fetch-blobs.sh` from TheMuppets `lineage-23.2`) and applies the port as `git am`-able patches (`patches/lineage-24.0/`). The synced source tree (~190 GB) lives in the gitignored `src/`.

The repo is public, for other gta4xl owners. Keep everything in English, generic and about this tablet only: no personal servers or domains, no internal CA certificates, no signing keys, no serial numbers, MAC or IP addresses, no details or paths of anyone's own machines.

## State and open points

1. The port is in daily use on one SM-P615 (Samsung firmware P615XXSAFYD1), signed with the owner's own keys and updated from an own update server, unattended. Hardware status: `README.md`. The test of every component is `tools/tablet-test.sh` (see *Testing*).
2. Kernel: the fork's `gta4xl-4.19` branch (Linux 4.19.325 with CIP's stable backports, see *Kernel*) is the default for `BRANCH=lineage-24.0`; its 4.14 predecessor (`gta4xl-24.0`) is archived.
3. Releases: a proof-of-concept build on GitHub Releases, signed with the test keys, without `WITH_ADB_INSECURE` and without an update server, built with this repository's `build.sh`. It is not installed on a device itself (the test tablet has its own keys). Images never go into git; the maintainer uploads them. No regular releases: users build and sign their own.
4. Open: calls and SMS, a GPS position fix, the headphone jack, Bluetooth audio, microSD, USB accessories; a device connected through the Wi-Fi hotspot (`HOTSPOT=1 tools/tablet-test.sh hotspot` checks the tablet's side only: the tethering service serves the interface and the forwarding rules are in place; `USB=1 tools/tablet-test.sh usb` does send traffic, from the computer the tablet is connected to); the TrustZone worker thread that was once seen spinning (see *Testing*); a fresh installation of exactly the release files; refreshing the proprietary files from newer Samsung firmware (see *Proprietary files*); the Mali CVEs without public fixes and the f2fs fixes the kernel's README lists. Delete `patches/lineage-24.0/` once LineageOS ships an official 24.0 for gta4xl (then it is only a `BRANCH` switch).

## Commands

Build the container image (only when `Containerfile` changes; `build.sh`, `patches/`, `tools/` and `vendor_blobs/` are bind-mounted from the checkout, so `git pull` needs no image rebuild):
```bash
podman build -t lineageos-gta4xl-builder .
```

Fetch the proprietary files once (and again when TheMuppets changes, see *Proprietary files*):
```bash
tools/fetch-blobs.sh
```

Prepare the bind-mounted directories once (the container runs as `builder`, uid 1000):
```bash
mkdir -p src ccache
podman unshare chown 1000:1000 src ccache
```
If the checkout's group is not mapped in the user namespace (a setgid group inherited from a parent directory), `podman unshare chown` fails with EPERM: run `chgrp "$(id -gn)" src ccache && chmod g-s src ccache` first. With a restrictive umask the checkout must be made world-readable (`chmod -R o+rX .`): the container user reads it as "others", and `build.sh` checks that before doing anything.

Full build, detached:
```bash
podman run -d --rm --security-opt label=disable \
    -v "$(pwd)":/home/builder/repo:ro \
    -v "$(pwd)/src":/home/builder/android/lineage \
    -v "$(pwd)/ccache":/home/builder/ccache \
    --name gta4xl-build lineageos-gta4xl-builder
```
(`--security-opt label=disable`: on SELinux hosts such as Fedora the container may not use home-directory files otherwise. Avoid `:z`/`:Z` on these mounts: relabeling walks the whole tree.)
Output: `src/out/target/product/gta4xl/lineage-24.0-<date>-UNOFFICIAL-gta4xl.zip` and `recovery.img`; the log ends with `>>> Build finished` and their checksums. Progress: `podman logs -f gta4xl-build` or `src/logs/build-<UTC>.log`. Add `-e SYNC_ONLY=true` to only sync, `-e SKIP_SYNC=true -e KEEP_GOING=true` for porting iterations, `-e WITH_ADB_INSECURE=true` for test builds (official LineageOS switch: `ro.adb.secure=0` + `ro.debuggable=1`, so adb is on and root-capable from the first boot, even after Format data); never publish such a build.

Own signing keys: `-e SYNC_ONLY=true` once, then `tools/make-keys.sh` (plain `signing/keys/` + encrypted `signing/signing-keys.enc`, both gitignored), then build with `-it` and `-v "$(pwd)/signing/signing-keys.enc":/home/builder/signing-keys.enc:ro`; `build.sh` asks for the password at the start (`SIGNING_KEYS_PASSWORD` for automation), detach with Ctrl+P Ctrl+Q.

Environment variables of `build.sh` (README has the user-facing table): `DEVICE` (`gta4xl`), `BRANCH` (`lineage-24.0`), `ROOMSERVICE_BRANCHES` (`lineage-23.2`), `LINEAGE_BUILDTYPE` (`UNOFFICIAL`), `KERNEL_REPO_URL` (the fork for 24.0, empty = manifest kernel), `KERNEL_REVISION` (`gta4xl-4.19`; `gta4xl-24.0` = the archived 4.14 kernel), `KERNEL_BPF_KVER` (`5.10.239`), `BLOBS_DIR` (`/home/builder/repo/vendor_blobs`), `PATCHES_ROOT` (`/home/builder/repo/patches`), `SIGNING_KEYS_FILE` (`/home/builder/signing-keys.enc`), `SIGNING_KEYS_PASSWORD`, `SYNC_JOBS` (4), `SYNC_RETRIES` (5), `BUILD_JOBS` (`nproc`), `CCACHE_SIZE` (30G), `REPO_GROUPS` (`default,-darwin,-mips,-notdefault`; empty = repo's default groups), `MIN_FREE_GB` (15), `SYNC_ONLY`, `SKIP_SYNC`, `KEEP_GOING`, `OTA_BASE_URL` (empty), `OTA_AUTO_INSTALL` (`false`), `FALLBACK_DNS` (`1.1.1.1 1.0.0.1`), `PRIVATE_DNS_HOST` (empty), `NTP_SERVER` (`pool.ntp.org`), `CAPTIVE_PORTAL_HOST` (empty), `DEBLOAT_PACKAGES` (eight apps), `TRUST_VENDOR_PATCH_FINAL`, `DEVELOPER_OPTIONS_VISIBLE`, `ADVANCED_RESTART` (all `true`), `WINDOW_BLUR` (`false`); an empty value disables a tweak. Anything else reaches the build system through the environment (e.g. `WITH_ADB_INSECURE`).

Tools (host-side; the tablet ones use `adb -s $SERIAL`, defaulting to the only attached device and refusing anything that is not a gta4xl):
- `tools/tablet-test.sh [test ...]`: 30 component tests over root adb with a logcat/dmesg/SELinux/crash delta per test; report in `build_output/tablet-test/<ts>/`. See *Testing*.
- `tools/tablet-setup.sh -a <apk_dir> -w <ssid>`: installs every APK (a subfolder = one split app via `install-multiple`), saves and connects Wi-Fi (`cmd wifi connect-network`; type from `list-scan-results`: PSK → wpa2, SAE only → wpa3; password prompted without echo; arguments single-quote-escaped for the device shell, since `adb shell` joins them into one command line).
- `tools/kernel-build.sh`, `tools/kernel-romtc-build.sh`, `tools/kernel-flash.sh pack|flash|check|restore`, `tools/kernel-cve-check.sh`, `tools/kernel_cve_dossier.py`: see *Kernel*.
- `tools/generate-ota-json.sh` (run by `build.sh` with `OTA_BASE_URL`), `tools/ota-upload.sh` (host, `OTA_REMOTE=user@host:/path`), `ota/Caddyfile` + `ota/ota.container`: see *Update server*.

Reset: `podman unshare rm -rf src ccache` (files under `src/` belong to a subordinate uid; plain `rm` fails), `podman rmi lineageos-gta4xl-builder`.

## Architecture

### Container and build pipeline
- `Containerfile`: Ubuntu 24.04 (`ARG UBUNTU_VERSION`) with the LineageOS build dependency list for Ubuntu 23.10+, installed with `--no-install-recommends` after a `dist-upgrade`, plus what that drops and the pipeline uses (`ca-certificates`, `openssl`, `patch`, `xz-utils`, `zstd`, `cpio`, `psmisc`, `lsof`, `procps`, `bsdextrautils`), `jq` and `repo`. No JDK: the Android toolchains (clang, rust, JDK, python, make, ninja, the kernel build tools) are prebuilts in the tree that need only glibc from the image. Rebuild it monthly with `podman build --pull --no-cache`. User `builder` (uid 1000; the image's own `ubuntu` user with that uid is deleted first), `CCACHE_DIR=/home/builder/ccache`, `safe.directory '*'` (bind-mounted trees belong to another uid). `ENTRYPOINT` is `/home/builder/repo/build.sh` from the checkout.
- `build.sh` (cwd = `src/`), `set -euo pipefail` with `set +u` from `source build/envsetup.sh` on (AOSP's shell tooling is not nounset-safe; never end a pipeline inside a command substitution with `head` under pipefail — a SIGPIPE ends the script silently; `sed -n 1p` reads to the end): log to `src/logs/build-<UTC>.log` via `tee` → free-space watchdog (background loop; below `MIN_FREE_GB` it kills the process group) → readability check of `PATCHES_ROOT`/`BLOBS_DIR` and presence of the blobs (before anything takes time) → signing keys (step 0, below) → revert `TWEAKED_FILES` to git state (sed/perl targets in lineage-sdk, frameworks/base, Connectivity, and `lineage_gta4xl.mk`; `repo sync` refuses to check out over local changes, and the edits are re-applied every build) → `repo init` (every run, so a changed `BRANCH` switches the manifest; retried like the sync, since a short DNS outage once ended a build right after the key password was typed) → kernel local manifest → `clean_interrupted_sync` + `repo sync -c --force-sync --retry-fetches=5` with retries and `GIT_HTTP_LOW_SPEED_LIMIT/TIME` (a fetch whose connection stays open while nothing arrives would hang forever) → `SYNC_ONLY` stops here → `vendor_blobs/` copied into `vendor/samsung/` (old copies removed first, so the checkout is always the source of truth) → `apply_patches` → `keys.mk`/`Android.bp` for own keys → UX edits → `ccache -M` → `breakfast gta4xl` (retried once after patching: on a fresh tree the device trees only arrive with breakfast, unpatched) → `apply_patches` again → Private DNS edit (optional, after the last `apply_patches`, since resetting a patched project would wipe it) → Trust edit → generated product additions → `m installclean` when they changed → kernel object directories removed when the kernel source is of another series than the objects in `out/` (kbuild does not clean up after a foreign tree) → `mka bacon` → checksums → update metadata (only with `OTA_BASE_URL`).
- Signals: bash as PID 1 ignores signals without a handler and runs a handler only after the foreground command ends, so long commands go through `run` (background + `wait`) and the INT/TERM handler kills the process group; the EXIT trap deletes `vendor/lineage-priv` (decrypted keys).
- `clean_interrupted_sync` (from the sibling monet/P80 builders): an interrupted sync poisons the next one. A project whose first fetch was killed has no `shallow` file, so repo treats it as manually unshallowed and fetches its complete history (tens of GB for prebuilts/clang); a project whose checkout was killed has HEAD at the right revision and is skipped with a half-empty worktree; stale `shallow.lock`/`*.lock` files make later fetches of that project fail (seen: four prebuilts projects carried stale `shallow.lock` files and ~1.3 GB of `tmp_pack_*` for days). The function removes such gitdirs/`.git` links, locks and temporary packs before every attempt. Nothing else may use the tree while `build.sh` runs.
- Kernel manifest (`.repo/local_manifests/zz-kernel.xml`, written every sync when `KERNEL_REPO_URL` is set): `remove-project` of `LineageOS/android_kernel_samsung_gta4xl` (`optional`, because `roomservice.xml` only exists after the first `breakfast`) plus the fork as `kernel/samsung/gta4xl`. The `zz-` name sorts after `roomservice.xml`, so the removal wins, and roomservice still finds the repository name in a manifest and does not add it again; `--force-sync` lets repo re-clone the path under the new project. An empty `KERNEL_REPO_URL` deletes the file. To test an unpushed kernel branch, bind-mount a clone (e.g. `-v "$(pwd)/kernel":/home/builder/kernel-fork:ro`) and set `KERNEL_REPO_URL=file:///home/builder/kernel-fork/android_kernel_samsung_gta4xl`; the container reads the clone as "others", so with a restrictive umask set `core.sharedRepository=0644` and `chmod -R o+rX .git` there.
- `apply_patches`: for every `patches/<BRANCH>/<project path>/` with `*.patch`, reset the project to `m/<BRANCH>` (the manifest revision) and `git am --3way` the series; a marker `applied-patches` in the project's gitdir (sha256 of the patch files + `m/<BRANCH>` + resulting HEAD) skips projects already in exactly that state. `repo sync --force-sync` resets the patched project on every sync, so in practice the series is re-applied every build. Files whose content ends up unchanged get their old mtime back (no new Soong/Kati analysis for an unchanged `Android.bp`/`*.mk`). A patch that stops applying fails the build with the project name. Projects not in the tree yet are skipped and patched after `breakfast`.
- Generated product additions: `vendor/gta4xl-builder/` (recreated every build), pulled in by `$(call inherit-product, vendor/gta4xl-builder/gta4xl-builder.mk)` appended to `lineage_gta4xl.mk` (the build fails if that file is missing, because the kernel version override lives there). A hash of the directory is stored in `out/.build-sh-tweaks`; when it differs, `m installclean` runs first, since images are packed from the `out/` staging dirs and would otherwise keep files of removed apps or overlays.

### Proprietary files
- `tools/fetch-blobs.sh` clones `TheMuppets/proprietary_vendor_samsung_gta4xl{,-common}` (branch `lineage-23.2`, or `BLOBS_REVISION`) into `vendor_blobs/` without `.git`, records the commits in `vendor_blobs/source.txt`, and leaves out `radio/` and the `add-radio-file-sha1-checked` lines of `gta4xl/Android.mk`. The result is byte-identical (`diff -r`) to the files the test tablet's builds use (checked again in November 2026: TheMuppets `bd4e4db` / `86a2304`).
- **Why no `radio/`:** it holds Samsung's P615XXS8FXE4 bootloader (`sboot`, `cm`, `keystorage`, `uh`, `up_param`) and modem (`modem`, `modem_debug`). `gta4xl-common/releasetools/releasetools.py` turns them into a firmware block in the updater script: only on `ro.boot.em.model == SM-P615`, only if `exynos9611.verify_no_downgrade()` passes and the bootloader is not already that version, it writes the boot chain into `bota` (applied by the bootloader at the next start) and the modem into `radio`/`cp_debug`; other models abort the installation ("Unsupported model, not updating firmware!"). The test tablet runs newer firmware (P615XXSAFYD1), so that block would be skipped anyway; leaving it out keeps the zip from ever writing the bootloader, and is the path every build of this port has taken. Consequence: users must update to Samsung's latest Android 13 firmware before installing (the LineageOS wiki requires Android 13 firmware for this device too), and the model check is gone (the device assert `gta4xl` remains, but our own recovery reports `gta4xl` on any hardware), so the README warns about the other Tab S6 Lite models.
- **Snapshot drift:** `repo sync` pulls the latest `hardware/samsung` and device trees every build. When upstream changes something that needs a matching blob-side change, TheMuppets gets it and the build dies early in Soong (`found in multiple namespaces`, `missing dependency`). First step: `tools/fetch-blobs.sh` again and `diff -r` against the previous `vendor_blobs/`. Past instance (2026-09): `hardware/samsung` added a dummy `libteecl` that collided with the prebuilt; fixed upstream by adding `"hardware/samsung"` to `soong_namespace.imports` in `gta4xl-common/Android.bp` (TheMuppets `86a2304`).
- **Newer Samsung firmware:** Samsung kept shipping P615 firmware after TheMuppets' snapshot (P615XXS9FXJ1 2024-11, P615XXSAFYD1 2025-04, P615XXUAFZB1 2026-02). SAFYD1's `/vendor` (2025-04-10) carries newer userspace: after a re-extraction with LineageOS's `extract-utils` (pinned RIL/Widevine/libcrypto-tm files kept, `radio/` skipped) only 14 files really change: 8 TEE trustlets (incl. keymaster, HDCP, PROCA), `camera.exynos9611`, `libexynoscamera3`, `libSEF.quram`. Not done yet: the trustlets run under the bootloader's TEE OS, so it needs testing (keystore/keymaster in logcat) on a tablet with that bootloader. The Wi-Fi firmware (`mx140.bin`, 2023-07-04) is byte-identical in SAFYD1; the kernel source of SAFYD1 brought two Mali fixes (in the fork) and one hotspot-only SCSC change (not ported).

### Signing
- Opt-in: `tools/make-keys.sh` (host; needs a synced tree for `external/avb/avbtool.py` and the `apex_key` list) generates the LineageOS wiki's 11 app certificates (RSA-2048: bluetooth cyngn-app media networkstack nfc platform releasekey sdk_sandbox shared testcert verity, plus `testkey.*` symlinks to releasekey) and one RSA-4096 key per plain `apex_key` in the tree (`private_key: "X.pem"` without `:` or `/`; ~110 on 24.0: `X.pem` + the public key named exactly as the module's `public_key` — usually `X.avbpubkey`, `com.android.vndk.pubkey` for VNDK — for the payload, `X.pk8`/`X.x509.pem` for the container). It calls openssl directly (AOSP's `development/tools/make_key` prompts for a password and always exits 1 through its EXIT trap). The set is tarred and encrypted (`openssl enc -aes-256-cbc -pbkdf2 -iter 600000 -md sha256`) into `signing/signing-keys.enc` (mode 644: the container reads it as "others"; the tool refuses to finish without the `Salted__` header; OpenSSL 1.1.1 and 3.x read each other's files). `-u` adds missing keys, `-o DIR` redirects output, `-s` sets the subject (default `/O=Android/OU=Android/CN=Android`).
- `build.sh` step 0 always deletes a leftover `vendor/lineage-priv`; with `/home/builder/signing-keys.enc` mounted it asks for the password (`read -rs < /dev/tty`, 3 attempts; fails loudly without a tty), decrypts into `vendor/lineage-priv/keys` (umask 077; outside every repo project, so sync ignores it) and unsets `SIGNING_KEYS_PASSWORD` (Soong dumps the environment into `out/soong.log`).
- Step 4 writes `keys.mk` + `Android.bp` there. Verified in the 24.0 Soong/Make sources: `vendor/lineage/config/common.mk` `-include`s `vendor/lineage-priv/keys/keys.mk`; `PRODUCT_DEFAULT_DEV_CERTIFICATE := vendor/lineage-priv/keys/releasekey` makes `certificate: "platform"`-style app certificates resolve in that directory (`DefaultAppCertificateDir`), yields `BUILD_KEYS := release-keys` (any path under `vendor/lineage-priv/`) and makes `apex_key` modules look for `X.pem`/`X.avbpubkey` there first (`ApexKeyDir`). The APEX *container* certificate is a separate `android_app_certificate` module resolved in the APEX's own directory, so only `PRODUCT_CERTIFICATE_OVERRIDES += <apex_module>:X.certificate.override` plus `android_app_certificate { name: "X.certificate.override", certificate: "X" }` in the keys dir re-signs containers; `build.sh` derives the list by scanning every `Android.bp` for `apex`/`apex_defaults`/`override_apex`-like modules (explicit `:X.certificate`, otherwise the longest key name that prefixes the module name, e.g. `com.android.virt_avf_enabled` → `com.android.virt`; VNDK uses the pseudo name `com.android.vndk`), and maps apps with a module-local certificate (`certificate: ":x"`, the APKs inside APEXes) to releasekey. Modules without a key keep AOSP test certs and are listed as a warning (`make-keys.sh -u`). Checked on the maintainer's builds with `apksigner`: only the CTS shim APEX stays on a test key (on purpose).
- Without keys everything is test-keys. Checked on a proof-of-concept build: all 150 installed APKs carry AOSP test certificates (testkey/platform/shared/media/networkstack), all 39 APEX containers certificates from the source tree, APEX payloads the in-tree `.avbpubkey`s, the OTA package the AOSP testkey (`META-INF/com/android/otacert`).
- Switching keys on a device: recovery sideload ("Signature verification failed" → Install anyway, or flash the new build's recovery first) + Format data (the platform certificate changed) + adb re-authorization. The LineageOS wiki's `key-migration/migration.sh` avoids the wipe. A switch between test and own keys costs one Soong re-analysis plus re-signing of every APK and APEX (the PoC's switch from own keys to test keys took 13 minutes on a warm tree).

### Tweaks
All are environment variables (empty = off) and generated into `vendor/gta4xl-builder/`:
- `FALLBACK_DNS`: NetworkStack's `config_default_dns_servers` (overlayable), which `DhcpClient.acceptDhcpResults()` only appends to a lease without DNS servers; DNS stays DHCP's, Private DNS stays `opportunistic`. NetworkStack lives in an APEX, so only an RRO works: `runtime_resource_overlay` `Gta4xlBuilderNetworkStackOverlay`, target `com.android.networkstack`, `targetName="NetworkStackConfig"`, priority 200 (> LineageOS's 100), shared with the connectivity check.
- `CAPTIVE_PORTAL_HOST`: `config_captive_portal_{http,https}_url` + `_fallback_urls` in the same RRO. Android needs a bare 204 over *both* http and https (a redirect counts as a captive portal), so `build.sh` curls both first and skips the overlay with a warning otherwise (a dead endpoint would mark every Wi-Fi as having no internet).
- `PRIVATE_DNS_HOST`: the default `opportunistic` mode is hard-coded, not a resource, so `perl` edits `ConnectivitySettingsUtils` (mode falls back to `hostname`, hostname to the host; Settings reads both through it) and `DnsManager` (read `PRIVATE_DNS_SPECIFIER` directly; rerouted through `ConnectivitySettingsManager.getPrivateDnsHostname()`); the build fails if the edits do not land. Off by default: strict DoT breaks networks that block port 853.
- `NTP_SERVER`: static overlay of `config_ntpServers` (an array since Android 14) via `PRODUCT_PACKAGE_OVERLAYS`. gta4xl-common still sets the old singular `config_ntpServer`, which Android 14+ ignores — that is why stock builds use `time.android.com`.
- `DEBLOAT_PACKAGES`: a generated `prebuilt_etc` (`Gta4xlBuilderDebloat`, installs the list as `/product/etc/gta4xl_builder_debloat.txt`) whose `overrides` keeps the listed modules out of the image. It must be a module type Soong exports overrides for *and* Make honours (`module-overrides` in `build/make/core/main.mk`: only PACKAGES/EXECUTABLES/SHARED_LIBRARIES/ETC): a `phony` accepts the property but drops it from its Make output, so nothing gets removed.
- `TRUST_VENDOR_PATCH_FINAL`: `TrustInterfaceService.getSecurityPatchStatus()` returns GOOD for `ro.vendor.build.security_patch` when it equals the device tree's `VENDOR_SECURITY_PATCH` (read from `BoardConfigCommon.mk` after `breakfast`; 2024-05-01, the level of TheMuppets' files). The date shown stays real; an older level is still rated normally. Note that Samsung has newer firmware (see *Proprietary files*), so the rating hides a real gap; it only stops a warning that nothing in this build can resolve.
- `DEVELOPER_OPTIONS_VISIBLE`: `DevelopmentSettingsEnabler`'s default `Build.TYPE.equals("eng") ? 1 : 0` → `1`. `ADVANCED_RESTART`: `PowerMenuUtils`' default for `LineageSettings.Secure.ADVANCED_REBOOT` `0` → `1` (no Settings UI for it exists in this branch).
- `WINDOW_BLUR` (default `false`): the device tree sets `ro.surface_flinger.supports_background_blur=1` in `vendor.prop`, and the Mali-G72 cannot keep up at 2000x1200 (median frame of the app drawer animation 37 ms with blur, 14 ms without, on either kernel). `build.sh` writes the property with 0 as a product property, which init loads after vendor; `true` keeps the tree's setting. On a running system: `settings put global disable_window_blurs 1`.
- Kernel version override: `PRODUCT_PRODUCT_PROPERTIES += ro.bpf.kver_override=$KERNEL_BPF_KVER` whenever `KERNEL_REPO_URL` is set (see *Kernel*).
- Video HAL and the kernel's headers: when the kernel source is 4.19 or newer, `build.sh` adds `soong_config_set_bool,openmax,MAINLINE_FEATURE_IN_SINCE_4_19,true`. Modules with `device_kernel_headers` compile against the uapi headers generated from the kernel tree, and 4.19's `v4l2-controls.h` defines the HEVC and VP9 control ids that `libExynosVideoApi`'s `exynos_mfc_media.h` otherwise defines again with Samsung's numbers (`-Werror`). The fork's MFC driver knows both sets of ids. The other open HALs keep `kernel-4.14-headers` from `hardware/samsung_slsi-linaro`, the closed ones (camera, RIL, sensors) the 4.14 ABI.
- **Property partition matters:** properties from a device-level product makefile via `PRODUCT_PROPERTY_OVERRIDES` (or `vendor.prop`) land on `vendor`, where `vendor_init`'s property_contexts silently deny anything without a `vendor.`/`persist.vendor.` prefix (`avc: denied { set }`): the build succeeds, the line is in `vendor/build.prop`, the property never exists at runtime. Use `PRODUCT_PRODUCT_PROPERTIES`/`product.prop` like LineageOS's own `ro.lineage.*` (seen twice: the update server URI, and FUSE passthrough, patch 0014).

### Update server
- With `OTA_BASE_URL=https://host[/path]` the build sets `lineage.updater.uri=<base>/api/v1/{device}/{type}/` (product partition) and `tools/generate-ota-json.sh` writes `out/.../ota/gta4xl.json` + a copy of the package. The JSON format was checked against the Updater's sources (`lineage-23.2`, `UpdatesNetworkDataSource.kt`/`NetworkUpdate.kt`): a JSON array of `{datetime, files[{filename, os_patch_level, os_sdk_level, sha256, size, url}], type, version}`, all read from the build's `build.prop` files. The package is picked by `ro.lineage.version`, never by `ls -t` (bacon hard-links `lineage-<version>.zip` to `lineage_gta4xl-ota.zip` and overwrites it in place, so older names can show new content).
- `tools/ota-upload.sh` runs on the host (SSH credentials never enter the build container) and checks the sha256 first. It sends the small files first and the package last over one shared SSH connection (`ControlMaster`), so a key's passphrase is asked once, at the start, and nothing needs attention after the long transfer. The metadata goes up as `index.json.new` and is renamed to `index.json` on the server only when the package is complete, so the Updater never sees an entry for a package that is not there, and an upload that breaks off leaves the previous build on offer; the package transfer keeps its partial data (`--partial-dir`) and continues on the next run. After publishing it deletes the older packages from `<remote>/gta4xl/` (`lineage-*.zip`, their `.sha256`, leftovers in `.rsync-partial/`; nothing else there), since the metadata only ever names the newest one; `OTA_KEEP_OLD=1` keeps them.
- `ota/Caddyfile` + `ota/ota.container`: rootless Podman Quadlet, Caddy serving plain HTTP on `127.0.0.1:8099`, `respond /generate_204 204`; TLS and Host routing belong to a reverse proxy in front (the Updater only accepts https; `enable` does not work on generated Quadlet units, `loginctl enable-linger` + `WantedBy=default.target` do).
- The Updater of a 23.2 build refuses packages with a higher `os_sdk_level` unless `lineage.updater.allow_major_upgrades=true`, so the first move to 24.0 is a recovery sideload.
- Unattended installs: `OTA_AUTO_INSTALL=true` (only with `OTA_BASE_URL`) sets `lineage.updater.auto_install=true`, read by `patches/lineage-24.0/packages/apps/Updater/0001`. Flow: a check when the tablet starts (after the first unlock) and weekly, a download on an unmetered network, an install when the screen is off and the device is idle, while charging or between 00:00 and 05:00. Rules: only the newest build is a candidate; its signed `metadata.pb` must show a newer build of the same SDK level; each package id is tried automatically once; download errors are retried after 30 min, then 1, 2, 4 and 8 h. Logs under the tag `AutoInstall`. Verified on the test tablet by both paths (the night window on battery; idle on the charger, 31 minutes after the screen went off, which is JobScheduler's idle threshold). The recovery partition is refreshed by Android after an update (`persist.vendor.recovery_update`).

### Editing patches
Commit on top of the applied series inside a container (files in `src/` belong to the container's uid; on the host, git may not see a project's `.git` and falls back to an enclosing repository):
```bash
podman run --rm -it --entrypoint bash -v "$(pwd)/src":/home/builder/android/lineage lineageos-gta4xl-builder
# cd device/samsung/gta4xl-common; edit; git commit; git format-patch -1 --stdout > /tmp/x.patch
```
Patches are `git format-patch -N --zero-commit --no-signature` files with the maintainer's public identity as author (see *Conventions*). To change an earlier patch, re-apply the series in a clone of the device repo at the base commit, amend and re-export the later patches too, so their `index` lines stay right. Never leave changes only inside `src/`: the next build resets patched projects.

## Porting notes

Model for the generic changes: the Galaxy A21s (Exynos 850, same slsi-linaro stack), whose `a21s-common` 23.2→24.0 commits list most of them. `patches/lineage-24.0/device/samsung/gta4xl-common/`:
- 0001 export `hardware/samsung_slsi/scsc_wifibt/wpa_supplicant_lib` as a Soong namespace (`lib_driver_cmd_slsi` moved into its own namespace; wpa_supplicant/hostapd could not resolve `BOARD_WPA_SUPPLICANT_PRIVATE_LIB`)
- 0002 drop `disable_configstore` (ConfigStore is gone in Android 17)
- 0003 drop `fastbootd` from `PRODUCT_PACKAGES` (24.0 adds it for every device)
- 0004 drop `PRODUCT_ENABLE_UFFD_GC` (default on 24.0)
- 0005 drop `TARGET_KERNEL_NO_GCC` (24.0 always builds kernels with LLVM)
- 0006 legacy libion: `soong_config_set_bool,libion,legacy_impl,true` + `device/lineage/sepolicy/libion/sepolicy.mk` (4.14 has legacy ION only, no DMA-BUF heaps)
- 0007 `libui legacy_gralloc` (gralloc 2.x/"gralloc3", no gralloc 4)
- 0008 VINTF device manifest `target-level` 6 → 7 (Android 17's lowest framework compatibility matrix is 7)
- 0009 `hardware/google/pixel` is split into per-component namespaces: `power-libperfmgr`, `thermal`, `pixelstats` (thermal imports pixelstats)
- 0010 `bt_did.conf` through `hardware/samsung_slsi/libbt`'s `bt_did.slsi.conf` module instead of `PRODUCT_COPY_FILES` (clash; `bt_vendor.conf` is gone from libbt as unused)
- 0011 the common `wpa_supplicant.conf` from `wpa_supplicant_lib` instead of our own copy (clash once 0001 exports the namespace)
- 0012 drop the vendor `sysfs_block` type: Android 17 declares it in `system/sepolicy/public` again ("Duplicate declaration of type")
- 0013 no explicit `<kernel target-level>` in the manifest (`assemble_vintf` rejects it at level 7)
- 0014 `persist.sys.fuse.passthrough.enable=true` from `vendor.prop` (denied for `vendor_init`, so FUSE passthrough was silently off on every build) to a new `product.prop` (`TARGET_PRODUCT_PROP`): `/sdcard` reads ~220 → ~416 MB/s, verified with checksums. An upstream bug worth reporting, not a port fix.
- 0015 `hal_gnss_default` may find `fwk_sensor_service` (Samsung's GNSS HAL feeds accelerometer/gyro data to the GNSS firmware through `libsensorndkbridge`; without it the MEMS assistance silently stays off; present on 23.2 too)
- 0016 include `device/lineage/sepolicy/libperfmgr` (the Pixel power HAL's thermal listener; log noise otherwise, also labels `vendor.powerhal.*`)
- 0017 SurfaceFlinger may read `vendor_hwc_prop` (LineageOS's SurfaceFlinger reads `vendor.display.vds_allow_hwc`; denial on every boot)
- 0018 drop `ro.apk_verity.mode` and `ro.product_ship` from `vendor.prop` (no property_contexts entry → `default_prop`, denied for `vendor_init`, never existed at runtime, nothing reads them)
- 0019 `dontaudit vendor_init vts_status_prop` (Samsung's `init.vendor.rilcommon.rc` mirrors `vts.native_server.on`, only ever set by VTS)
- 0020 `dontaudit gpsd` searching `/data/data` (the Broadcom blob probes for SPOT debug tools; an MLS constraint, not a missing rule)
- 0021 `cass` (Samsung's modem monitor) may connect to rild's `@VND_Multiclient` socket: it retried once a second, ~550 denials per ten minutes, wrapping the 2 MB kernel log in ten minutes and triggering the audit rate limit, which then drops unrelated denials. Verified by loading the shipped CIL with the rule (`load_policy`).
- 0022 label `/sys/kernel/mm/vmscan/mem_boost_mode` `sysfs_camera_writable` (Samsung's kswapd boost when a camera opens; `init.exynos9611.rc` already chowns it to cameraserver, the generic `sysfs` label blocked it) and `dontaudit` the camera HAL's lookup of the AIDL allocator (this device only has HIDL gralloc 2.0). Verified with `load_policy` too.
- 0023 `rild` may create a directory of type `log_vendor_data_file`: with a SIM in, Samsung's RIL creates `/data/vendor/log/err` when it starts and was denied at every boot (`comm="ICR"`); the common policy only lets it use such directories and create files in them. Until a build with this patch has run on the test tablet, `tools/tablet-test.sh` keeps the denial among its known lines.

Other projects:
- `packages/apps/Updater/0001`: unattended installation of updates (see *Update server*).
- `packages/apps/Settings/0001`: a switch "Sleep when cover is closed" under Display (only where the overlay sets `config_lidControlsSleep`): one `lineageos.preference.GlobalSettingSwitchPreference` with the key `lid_behavior` and strings in new resource files (`res/values{,-pl}/cover_sleep_strings.xml`, so the patch does not depend on the translated string files). No Java: `PhoneWindowManager.getLidBehavior()` reads `Settings.Global.LID_BEHAVIOR` on every lid event (1 sleep, 0 nothing). A worn cover or a weak magnet otherwise switches the screen off while the tablet is in use. To try it: `sendevent /dev/input/event9 5 0 1; sendevent /dev/input/event9 0 0 0` (the `hall` device, `SW_LID`).
- For a build error in a project this repository does not patch, look at that project's newest commits and at its open changes on LineageOS's Gerrit (`review.lineageos.org/changes/?q=project:LineageOS/<repo>+branch:lineage-24.0+-age:10d`; the author's other open changes of the same days usually belong together) before writing a fix. If such a change is needed before LineageOS merges it, carry it unchanged under `patches/lineage-24.0/<project path>/`. A carried patch has to go as soon as upstream merges it, and the build will not say so: in a tree that once had the patch applied, `git am --3way` finds the old objects in the local store and skips an already-merged patch as "already applied" (silently with `-q`), while a fresh shallow clone has no preimage and stops at the patch step ("sha1 information is lacking or useless ... could not build fake ancestor"). Before a release, look up every carried change on Gerrit and apply each patch set to a fresh `git clone --depth=1` of its project.

Android 17 and the eBPF loaders: the stock gta4xl kernel reports 5.4 to `bpfloader`/`netbpfload`/`netd` (uname spoof in `kernel/sys.c`) and lacks ring buffers, mmapable maps, `SOCK_RELEASE`, BPF iterators/LSM. Without the fork, Android 17 needed four platform patches (NetBpfLoad's "25Q4 requires kernel 5.10" back to a warning, netd's 5.4 stats programs past 25Q4, ConnectivityService without the ring-buffer consumers whose constructor aborts system_server, the Rust bpfloader's ring-buffer test program gated on 5.10); with the fork and `ro.bpf.kver_override=5.10.239` all of them became unnecessary and were dropped. `ro.bpf.kver_override` alone, as the official 4.14 devices use it, does NOT work with the stock kernel (boot loop); so an empty `KERNEL_REPO_URL` on lineage-24.0 does not boot.

General 24.0 lessons:
- `soong_build` for Android 17 needs more than 30 GB of RAM; with less, a full Soong analysis takes ~30 min of swapping (a partial one after small changes 7–15 min). Batch fixes, prefer one `KEEP_GOING=true` run over repeated attempts.
- Never write into `src/` outside `out/` between builds: Soong re-runs every glob whose directory changed and a changed result starts the full analysis (`Globs changed, rerunning soong... One culprit glob` names the cause). Run Python tools from the tree with `python3 -B`.
- Boot loops before adb: the reboot reason survives in `/metadata/bootstat/persist.sys.boot.reason` (readable from the recovery's adb shell); `/proc/last_kmsg` on this Samsung is the S-Boot log of the last few starts (it names the reset cause, for example "WATCHDOG RESET"). The 4.19 kernel keeps the kernel log of the start before in `/proc/gta4xl_last_kmsg` (root), however that start ended, and `/proc/reset_reason` says what the bootloader saw (`RPON` restart, `KPON` panic, `DPON` watchdog). To get logs instead of a loop, temporarily comment out `reboot_on_failure` in `netbpfload.35rc`/`netd.rc` and the `wait_for_prop bpf.progs_loaded` in `netbpfload.rc` in a dev tree — never in `patches/`.
- Known and accepted on this kernel: SensorService `addFrozenStateChangeCallback ... error=-38` (binder has no frozen-state notifications), lmkd's two `KVER_6_1`-gated memevents programs missing. Boot warnings on every kernel for this tablet: `a96t3x6 device_create_file` ×1, `rt5665 gpio_to_desc` ×2. After the gyroscope was used, the sensor hub driver saves its calibration to `/efs/FactoryApp/gyro_cal_data` with `O_CREAT`; the kernel asks for CAP_DAC_OVERRIDE on the directory, SELinux logs a `dac_override` denial for the kernel domain, and the write goes through because the file exists.

## Kernel

Fork `6Xkljk8Vj7Tk1k4/android_kernel_samsung_gta4xl`, branch `gta4xl-4.19` (GitHub's default). Its `README.md` is the public description: what works, where each driver comes from, measurements, security state, what is open. New fixes go on top as single commits with the upstream reference (`commit X upstream` / `cherry picked from commit X`), no parallel branches. Branch `gta4xl-24.0` is the previous kernel (4.14 with the eBPF 5.10 backports), archived.
- **Why 4.19:** Samsung never released a kernel newer than 4.14 for the Exynos 9611, 4.14 stable ended in March 2026, and mainline has no Wi-Fi, modem, camera or audio for this SoC. Samsung's 4.19 tree for the Exynos 850 (`LineageOS/android_kernel_samsung_exynos850`, `lineage-24.0`) is the closest driver generation: Mali, SCSC Wi-Fi/BT, MFC, scaler, ION are the same families, and the closed Android components keep working.
- **What the branch is:** that tree at `b8c71b7aecec` (4.19.325) + this tablet (device trees unchanged from 4.14, so DTB and DTBO are byte-identical to the 4.14 build; the firmware-coupled code from the tablet's 4.14 kernel: cal-if, ACPM with its plug-in firmware, PMU, TMU, UFS and USB PHYs, PMIC, charger, display, camera, audio, modem, touch, S Pen, sensor hub, tzdev) + fixes to the tree (CPU hotplug with cluster power-down, thermal limits, suspend and power modes, reset reasons for this bootloader, performance) + the security fixes + CIP's `linux-4.19.y-st` merged (`uname -r`: `4.19.325-st21-g<commit>`).
- **What the ROM does for it** (all in `build.sh`): the local manifest, `ro.bpf.kver_override=5.10.239`, the video HAL flag (see *Tweaks*), and removing the kernel object directories when the series changes.
- **Leave off:** `CONFIG_DEBUG_INFO_BTF` (Android's loaders do not need kernel BTF, and on the 4.14 branch it made the kernel refuse every BPF program) and `CONFIG_JUMP_LABEL` (static keys do not flip on this tree: netd's BPF start-up test aborts and Android does not come up).
- **Kernel-only test flow:** `tools/kernel-build.sh [branch]` builds a clone of the fork standalone in a `kbuild-llvm` container (Ubuntu 26.04 + clang/lld, `LLVM=1 LLVM_IAS=1`; no Android tree; a few minutes; not next to a ROM build on a small host). `tools/kernel-romtc-build.sh KSRC OUT` builds it with the ROM's clang, host tools and make flags from a synced tree: run it before any ROM build with a changed kernel, a kernel that only builds with the distribution's clang fails the ROM build hours in. `tools/kernel-flash.sh flash|check|restore` repacks the Image into the last ROM build's `boot.img` (header and properties from `unpack_bootimg`), adds the AVB hash footer and builds `vbmeta` exactly like `build/make` (`--algorithm NONE`: this ROM's vbmeta is unsigned, the bootloader is unlocked) and writes both with root adb `dd` (Samsung has no fastboot; vbmeta carries boot's hash, so the pair must match). It refuses unless the tablet runs exactly the build in `src/out` and keeps one boot+vbmeta backup per installed build (`build_output/kernel-flash/backup/<ro.build.date.utc>/`; after an update an old vbmeta would boot-loop); `restore` works from the recovery too.
- **What the kernel does when it fails:** a panic in the first two minutes after the start, or a start whose predecessor died in that phase, ends in the recovery, so a kernel that cannot come up does not loop; later a panic restarts Android. `/proc/gta4xl_last_kmsg` (root) has the log of the start before, `/proc/reset_reason` what the bootloader saw. Both partitions carry the same kernel after a ROM update, so a kernel that hangs in the recovery too needs Download mode (`heimdall flash --BOOT boot.img --VBMETA vbmeta.img --RECOVERY recovery.img` with the images of the installed build). `make exynos9611-gta4xl_defconfig gta4xl_test.config` builds a test image that resets to the recovery after 90 s and never suspends; never put one into a build for others.
- **Traps of this tree:** `make clean` fails (`drivers/misc/tzdev/tests/Makefile` is missing), so after a configuration change delete the objects by hand or stale ones stay (they also count as compiled for the CVE check). The defconfig is a minimal one and options select each other: after changing it, diff the resulting `.config` with the previous one and explain every line that was not asked for (a trim once dropped `CONFIG_I2C`, and with it PMIC, charger and pen). The bootloader ignores the boot image's command line: kernel options go into `CONFIG_CMDLINE`. Values written for the bootloader are a protocol with this bootloader, not the donor board's (the reset reason prefix is `0x12345670` here). A patch that applies cleanly can still be wrong or break the build: build, and read the function.
- **Before removing a kernel option,** look for its users in the Android tree and in `kernel/configs/*/android-4.19/android-base.config`, not only for the reason to remove it. `tools/tablet-test.sh vintf` lists what the framework's compatibility matrix asks for and this kernel lacks, and `tools/tablet-test/kernel-config-waivers.txt` holds the reason for each of the 17 that are left out. Tethering was once broken that way: netd attaches the FTP and the PPTP connection tracking helper when it enables forwarding (`TetherController::setForwardRules`), and without the PPTP helper the whole rule batch fails (`xt_CT: No such helper "pptp"`, `dumpsys tethering`: `lastError = 8`).
- **Suspend and resume:** nothing that an interrupt or a non-freezable worker can run between "tasks frozen" and "tasks restarted" may touch a file or start a usermode helper; storage is the last device back. The Wi-Fi driver did (a file lookup under the interface mutex when the access point dropped the tablet during sleep), and the tablet hung in resume until the watchdog reset it; the signature of such a hang is S-Boot's "WATCHDOG RESET" in `/proc/last_kmsg` after the resume thread's last line, and `DPON` in `/proc/reset_reason`. With the USB cable to a computer in, Android never suspends; `pm_test` (`echo devices > /sys/power/pm_test; echo mem > /sys/power/state`) runs every driver's callbacks without powering down, and `tools/tablet-test.sh suspend` does that.
- **Monthly routine:** `git fetch --no-tags cip linux-4.19.y-st && git merge cip/linux-4.19.y-st` (remote `cip`: `https://git.kernel.org/pub/scm/linux/kernel/git/cip/linux-cip.git`), with two rules: `fs/f2fs` is never taken from CIP (this tree's f2fs is far ahead of 4.19's; CIP's f2fs fixes have to come from mainline one by one), and a hunk that merges cleanly into a function the vendor changed is read before it is believed (the first merge had one that would have crashed USB tethering). Then both builds, DTBs compared with the previous ones, objects deleted and rebuilt, `tools/kernel-cve-check.sh` (a merge can bring a bug whose fix CIP lacks), `tools/tablet-test.sh`.

### Security work (summary; details in the commit messages and the fork's README)
Threat model: what a host on the same network, an access point, a malicious app or a compromised browser renderer can reach. Every fix of the 4.14 branch is on `gta4xl-4.19`; the donor tree lacked the Mali, ION and SCSC fixes although it has the same driver generation.
- **Mali `bv_r38p1`** (`CONFIG_MALI_BIFROST_R38P1`, Samsung-modified DDK r38p1; Mali-G52 is job-manager, `csf/` not built). Evidence: NVD (`Bifrost GPU Kernel Driver`) + CISA KEV, and the Google Nest mirror of Arm's GPL DDK drops (`nest-open-source.googlesource.com/manifest_repos/mali-driver`, pristine r38p1…r47p0) to `diff -r` against Samsung's tree. Samsung had fixed CVE-2022-38181, CVE-2023-4211 and most likely CVE-2023-28147. CVE-2023-26083 (KEV) only looked fixed: the r38 drops compile the "development" default `kbase_unprivileged_global_profiling = 1`, so every app could open the kernel-address-leaking timeline stream — default 0 as in r43p0. CVE-2024-4610 (KEV): r41p0's `no_user_free_refcnt` + `kbase_is_region_shrinkable()` backported from r42p0. Plus two driver fixes from Samsung's P615XXSAFYD1 source. Still open: CVE-2024-0671 (r49p0), CVE-2025-0427 (r49p4) — fixes newer than any public DDK; CVE-2022-46395/46891 and CVE-2023-5249 sit in the same r41/r42 area but were not verified individually.
- **App-reachable surface** derived from the device's real SELinux policy (pulled CIL, set expressions): `untrusted_app` gets binder/hwbinder, ashmem, `/dev/mali0`, `/dev/ion` (open/ioctl/map, no write), ptmx, userfaultfd, memfd, netlink_route reads; no perf_event, no bpf. Samsung's Exynos ION: `ION_FLAG_NOZEROED` (unzeroed pool-miss pages, readable through a Mali dma-buf import) and `ION_FLAG_PROTECTED` were honoured for any caller — now stripped for UIDs ≥ 10000 (the graphics allocator runs as `system`, mediacodec as 1046, so HALs keep them); `ion_hpa_allocate()` truncated the length to 32 bits before the chunk-count check; `tzdev` `ion_fd2phys_v1.c` walked PFNs without clamping to the dma-buf size.
- **SCSC Wi-Fi** (full-MAC: the firmware does MLME, the driver's `rx.c` parses the firmware's frames itself, Samsung-only code without an upstream CVE feed): six RX parser fixes — `sta_wmm_update_wmm_ac_ies()` copied AC records into `wmm_ac[4]` without a bound (any AP's association response, before keys: the one real remote write), negative IE length for a (re)association response shorter than its fixed fields, GSCAN `ie_len < 0`, MBSSID sub-elements not bounded by the outer element, RSN/WPA AKM suite walk past the element, missing minimum lengths for received frames, scan pass-through, deauth/disassoc and RCL lists. Left alone as firmware-trust only: `mib.c` length wrap, regdomain rule count, `cac.c` WMM action length. Unreviewed: NAN, the TX/cfg80211_ops side, `drivers/misc/samsung/scsc` (HIP/mbulk). The driver never calls `cfg80211_{rx,tx}_mlme_mgmt` or `cfg80211_rx_assoc_resp`; cfg80211 fixes CVE-2026-98340 (reachable through scan results), CVE-2026-93805/93806 (defence in depth) are in.
- **Network stack:** memory-safety bugs a host on the same Wi-Fi can trigger with Android's defaults (RA Route Information length, IGMP and MLD query use-after-frees, `icmpv6_rcv`, the DAD failure race), DoS/leak/privacy fixes (old ACKs in the TCP fast path, PMTU exception dst leak, fnhe rebinding, temporary IPv6 addresses after prefix deprecation), CVE-2026-98432 (IPv4 options of a request socket freed while a retransmitted SYN still builds a SYN-ACK; remote, needs a TCP listener; it had first been judged "skipped" as a big TCP-core port — re-check such verdicts when a vendor rates a CVE critical). Judged unreachable on this configuration with Android's defaults: conntrack helpers (no auto-assign; only a tethered device reaches the two that netd attaches), MIPv6 HAO/RH2, jumbograms, seg6 (sysctl off), the fragment timer with `ipfrag_time ≤ 0`, tunnels (down or not built), SCTP/TLS/Bluetooth sockets/ipset/openvswitch (not built).
- **Browser sandbox and CISA KEV:** binder use-after-frees CVE-2026-64469/64468, CVE-2025-38352 (KEV, exploited on Android: posix CPU timer against a reaped task), CVE-2026-64370, CVE-2026-98507 (anon_vma publish barrier, arm64), CVE-2025-40040, the USB-chain KEVs CVE-2024-50302 (HID) and CVE-2024-53197 (USB audio), CVE-2026-64109 (AF_UNIX `tail->len`), the pipe fasync use-after-free CVE-2026-99203 (any app), netlink CVE-2026-99201/99211, `fib_rebalance` CVE-2026-99121, and two that any app reaches: CVE-2026-52910 (reuseport cBPF program freed without RCU) and CVE-2026-98276 (`SIOCGSTAMP` against `bind()`). Every Linux entry of the KEV catalogue was checked: fixed here, not built, or introduced later.
- **Only on 4.19, reachable by an app:** CVE-2024-26759 (zram swap-in without the swap cache races between threads: lost writes in app memory), CVE-2024-26640 (TCP receive zero-copy mapped page cache pages), CVE-2026-97958 (`RTM_GETCHAIN` loop under RTNL). Lessons: a backport marker in the history is not the code in the tree; a verdict carried over from 4.14 can rest on a 4.14-only reason; porting a fix can make the tool list the fix's own follow-up.
- **Config:** `SLAB_FREELIST_RANDOM/HARDENED`, `BUG_ON_DATA_CORRUPTION`, `SECURITY_DMESG_RESTRICT`, `PANIC_ON_OOPS`, `SYN_COOKIES`, `INIT_STACK_ALL_ZERO` (no measurable cost), `init_on_alloc`; removed: about 40 HID quirk drivers and hiddev, exotic USB host drivers, RC/IR, DVB/ISDB-T/FM, NTFS/cramfs/ecryptfs, KNOX NCM, PPP/PPTP/L2TP, sit/ip6tnl/vti/MIPv6 (sit0/ip6tnl0 accept packets even unconfigured), conntrack helpers other than FTP and PPTP, KSM, `UEVENT_HELPER`. `BPF_UNPRIV_DEFAULT_OFF` would be pointless: NetBpfLoad writes 0 to `unprivileged_bpf_disabled` every boot because system_server needs BPF maps, and SELinux is the gate. `perf_event_paranoid=-1` is AOSP's intent. Software PAN and the Spectre-v2 firmware call are kept; `gta4xl_fast.config` turns both off for speed (the fork's README has the numbers).
- **Monthly review:** `tools/kernel-cve-check.sh [OBJDIR]` clones/updates the kernel CNA's `vulns.git` into `build_output/kernel-cve/` and runs `tools/kernel_cve_check.py` over two surfaces, "net" (`net/`, `include/net/`, Wi-Fi, PPP) and "sandbox" (futex, memory, AF_UNIX/scm, epoll/eventfd/pipe/timerfd, signals/timers, binder, ashmem, iov_iter): per CVE `programFiles`, the introduced-in version, `.sha1`, `.dyad`, `.cvss`; filtered to files this build compiles (headers through kbuild's `.*.o.cmd` lists), introduced ≤ 4.19 or backported in, fix not referenced by a backport marker (never `Fixes:`); for AV:N/AV:A, unscored, or (sandbox) high-impact local CVEs it dry-runs the oldest stable fix with `git apply --check`. Only CVEs without a decision are printed: `tools/kernel-cve-triage.tsv` holds the decisions from the 4.14 kernel that still hold, `tools/kernel-cve-triage-4.19.tsv` those that depend on this tree (the 4.14 verdicts `backported`, `not-built` and `not-present` come back as `recheck` until it decides them); record every decision in the second file. `tools/kernel_cve_dossier.py VULNS KERNEL TRIAGE REPORT_DIR OUT_DIR [VERDICT] [BATCH_SIZE]` writes one dossier per CVE for a review of many at once. ~7 min, read-only for the kernel tree, patch fetches cached. CNA vectors overstate a lot: judge reachability on this configuration and Android's defaults (untrusted apps cannot read `/proc/net`; `min_supported_target_sdk` is 28). State in November 2026: about 630 CVEs touch compiled files, about 250 are open, each with a verdict, none undecided.

## Device facts and installation

- Non-A/B with dynamic partitions (`super`), separate `recovery` (71106560 bytes), `boot` (61865984), `dtbo`, `vbmeta`, `cache`. The zip writes the dynamic partitions, `boot`, `dtbo` and `vbmeta` (`gta4xl-common/releasetools`), not `recovery`; its `recovery.img` copy is only for two-step packages.
- No fastboot. Download mode: device off, hold Volume Down + Volume Up and connect USB, Volume Up to continue. Recovery: Volume Up + Power with USB connected; force-restart: Volume Down + Power 8–10 s. After flashing the recovery, boot straight into it, or Samsung's system replaces it. LineageOS's wiki installs the recovery with samloader-rs (`samloader flash --partition RECOVERY recovery.img --no-reboot`); Odin takes a `tar -H ustar` of `recovery.img` (`.tar.md5`: the tar plus `md5sum -t` of itself appended), Heimdall `--RECOVERY recovery.img`.
- Firmware: the wiki requires Android 13 firmware; `getprop ro.boot.bootloader` shows the bootloader version (test tablet: P615XXSAFYD1), `gsm.version.baseband` the modem.
- Root shell for partition work: the recovery's adb is root; on a running build, Developer options → Rooted debugging + `adb root` (userdebug builds with `ro.debuggable=0` allow it through that switch).
- `/dev/block/by-name/` exists; boot is also reachable as `/dev/block/platform/13520000.ufs/by-name/boot` (the updater script uses that path).

## Testing

`tools/tablet-test.sh [test ...]` (root adb) runs 30 parts one after another and after each one counts the new logcat E/F lines, SELinux denials (grep `avc: *denied` — the kernel logs two spaces), crashes/ANRs and kernel warnings since it started, listing the lines not matched by the known-noise regex `KNOWN`. It keeps the screen on with `svc power stayon`, puts back what it changes (Wi-Fi as it was, Bluetooth, location, brightness, media volume; the photos and the clip it takes are deleted) and exits with the number of failures. `camera`, `video` and `apps` wait up to `UI_WAIT` s for an unlocked screen; `HOTSPOT=1`, `USB=1` (adb drops at each switch) and `REBOOT=1` (the tablet then waits for its PIN) add optional parts.
- **Where the checks come from:** LineageOS's device support requirements (`github.com/LineageOS/charter`, `device-support-requirements.md`: userdebug, no `su`, SELinux enforcing, governors and I/O schedulers from its lists, no forced fast charge over USB, the Wi-Fi and Bluetooth addresses stored at the factory, display size and density as on stock, hardware codecs, both cameras, sensors, GNSS, RIL, USB functions, SD card), Android's VTS (`test/vts-testcase/kernel/api/sysfs`; VINTF through `vintf` on the tablet: manifests, matrices, kernel configuration, every HAL of the device manifest registered), and what broke on this tablet during the port (CPU capacities, thermal zones bound, eBPF loaded, CPU hotplug including the big cluster as a whole, one suspend/resume cycle of all drivers, the reset reason and the end of `/proc/gta4xl_last_kmsg`, the crash store, no kernel thread keeping a core busy).
- **Parts:** `system`, `services`, `kernel_api`, `vintf`, `storage` (throughput, FUSE passthrough, UFS wear, free space, SD card), `memory_cpu`, `cpu_hotplug`, `thermal_battery` (wear, charging state, input current limit on a data port), `display`, `input` (the touch and S Pen controllers' own connection tests through Samsung's `sec` sysfs nodes; only queries, the raw-data tests take the panel out of operation), `sensors`, `wifi`, `network_services`, `bluetooth`, `cellular` (with a SIM: registration, and mobile data with Wi-Fi off), `gps`, `audio`, `tee`, `codecs`, `screenrecord`, `camera`, `video`, `apps` (every launcher activity of a system package, never the apps the owner installed), `updater` (only with an update server), `packages`, `security`, `suspend`, `hotspot`, `usb`, `reboot`.
- **Pieces:** checks that run on the tablet are `tools/tablet-test/*.sh` (they report through `ok`/`no`/`nfo`; the tablet's shell counts in 32 bits). `kernel-config-waivers.txt` and `hal-waivers.txt` there list, with reasons, the kernel options and HALs that are missing on purpose, so that anything else missing fails. Java tools run with `app_process` from `tools/tablet-enctest/enctest.dex` (committed; `tools/tablet-enctest/build.sh` rebuilds it with the tree's JDK and d8; nothing is installed on the tablet): `EncTest`/`DecTest` (each hardware encoder makes 30 frames, ffmpeg on the host puts them into a container, the matching decoder decodes them), `SensorTest` (builds a system context by reflection and registers for each sensor like an app), `AudioLoop` (a 1 kHz tone on the media stream has to arrive at the microphone 20 dB above that frequency's level before it; root needs no permission for recording), `GnssTest` (becomes the system uid, because the location service only accepts a caller under a package name of its uid; prints no position). `tools/tablet-test/media_check.py` (host: Pillow, numpy, ffmpeg) decodes the photos of both cameras and the clip and measures the clip's sound: a dead microphone path records digital silence.
- **Facts it turned up:** Android sets neither `fs.protected_symlinks` nor `_hardlinks`; `screenrecord`/`screencap` fail with `UNASSIGNED_LAYER_STACK` while the display is off; the SoC does not suspend while USB with adb is attached; `sys.usb.state` is empty on this tablet (the gadget is configured by the AIDL HAL: read `dumpsys usb` and the configfs links); two volume key events do not always cancel out; tethering needs the PPTP connection tracking helper (see *Kernel*); the device manifest still declares `graphics.composer@2.4` although the AIDL composer runs, and a second SIM slot this model does not have; the hotspot's interface is `wlan1`, and the Wi-Fi client is off while it runs (no client and access point at once on this chip; Android switches the client back on afterwards); the kernel refuses a suspend when an alarm is due within two seconds (`Callback failed on alarmtimer ... returned -16`), so the test tries the driver cycle again; the kernel log has to be cut at its own clock (`dmesg`'s timestamps), not at `/proc/uptime`, which counts the time spent in suspend; with a SIM in, rild's `ICR` thread is denied creating `err` under `/data/vendor/log` at every start (its error log, nothing else depends on it).
- **A TrustZone worker thread that kept running** (seen once, cause unknown): after an unlock `tz_worker_thread/4` used a whole core for 38 minutes, the other seven workers 14 % each, with 44 000 rescheduling interrupts per second; the battery discharged on the cable. The secure OS kept its request mask at that one core (`cpu_mask = 0x10`, `user_cpu_mask = 0`): the worker entered it 5600 times a second and every entry returned at once, and tzdev wakes all workers after every return while the mask is not empty. It stopped when the core was taken offline and online again and a keystore operation followed (`echo 0 > /sys/devices/system/cpu/cpu4/online; echo 1 > ...`); a restart clears it too. The tzdev driver and its configuration are those of the 4.14 kernel. The test fails on a kernel thread that keeps half a core busy. To read a kernel variable of the running kernel without a debugger: addresses from the ROM build's `vmlinux` (`llvm-nm`), the load offset from one function in `/proc/kallsyms` (`kptr_restrict` to 1 and back), then a kprobe event `p:name function arg=+0(@0xADDRESS):u32` in a tracing instance.

## Host notes

- Disk: the 24.0 tree is ~190 GB without `out/` (with the darwin/mips groups ~20 GB more), `out/` ~135 GB after a full build, ccache up to `CCACHE_SIZE`. The watchdog stops the build before the disk fills.
- Time on an 8-core/16-thread desktop with ~30 GB RAM: a full build ~4.5 h (Soong analysis ~33 min swap-bound, then siso — Android 17's ninja replacement — CPU-bound at ~16 parallel jobs for ~3.9 h, holding ~21 GB itself); an incremental monthly build with a warm `out/` and ccache 20–60 min; the Java/Kotlin phase after a `frameworks/base` change thrashes with 16 JVMs on 30 GB (harmless, slow; lower `BUILD_JOBS` helps). Do not run two Android builds or a kernel build next to one on such a host.
- Rootless Podman: `--userns=keep-id` only works when the host uid is 1000 and the home directory is traversable by subordinate uids; otherwise use the `podman unshare chown 1000:1000 src ccache` recipe. Files under `src/` then belong to a subordinate uid: read them normally, delete with `podman unshare rm -rf`, run git on them inside a container.
